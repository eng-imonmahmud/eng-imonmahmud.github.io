Secure Scalable Application Platform on AWS

A production-grade, highly available, and scalable cloud architecture deployed entirely via Infrastructure as Code (Terraform). This project demonstrates enterprise cloud engineering best practices, focusing on robust networking, dynamic auto-scaling, and secure access management without the need for Bastion hosts or SSH key pairs.

---

Architecture Overview

This project builds a resilient 2-tier web application architecture within AWS. Traffic flows from an internet-facing Application Load Balancer into private-like compute nodes secured by strict Security Groups and managed via AWS Systems Manager.

Features & Services Used

  • Amazon VPC & Networking: Custom VPC, Internet Gateway, Route Tables, and dual-AZ Public Subnets.
  • Application Load Balancer (ALB): Distributes incoming web traffic across healthy EC2 instances. Configured with Access Logging directly to S3.
  • EC2 Auto Scaling: Dynamically scales compute capacity (min: 1, max: 3) using a Launch Template.
  • AWS Systems Manager (SSM): Instances are managed exclusively via SSM Session Manager. Zero SSH keys were generated or deployed, ensuring enterprise-grade instance security.
  • AWS IAM: Least-privilege IAM roles and Instance Profiles to grant EC2 instances SSM capability and ALB S3 writing permissions.
  • Amazon S3: Private bucket with strict Bucket Policies and Public Access Blocks to securely store Application Load Balancer access logs.

    • Security Posture

    1. Zero Inbound SSH: Security Groups on the EC2 instances strictly allow inbound HTTP from the ALB *only*. All other inbound traffic, including SSH, is blocked.

    2. Session Manager: Server access is handled via AWS SSM.

    3. Encrypted State: Terraform state and sensitive configurations are strictly ignored from source control.

    4. No Hardcoded Secrets: All configurations use data blocks and variables.

    Infrastructure Workflow & Deployment

    Prerequisites

  • AWS CLI authenticated locally.
  • Terraform v1.5.0+ installed.

    • Folder Structure

    text
    .
├── provider.tf           # AWS Provider configuration
├── versions.tf           # Required TF & Provider versions
├── variables.tf          # Parameterized inputs
├── locals.tf             # Common tags and naming conventions
├── vpc.tf                # VPC, Subnets, IGW, and Routing
├── security.tf           # Security Groups (ALB & EC2)
├── iam.tf                # Instance Profiles and SSM Roles
├── s3.tf                 # ALB Access Logging Bucket
├── alb.tf                # Load Balancer, Listeners, Target Groups
├── ec2.tf                # Launch Templates and ASG
└── outputs.tf            # Exported IDs and DNS endpoints

    Deployment Instructions

    1. Initialize the working directory:

    `bash

    terraform init

    `

    2. Format and Validate code:

    `bash

    terraform fmt -check

    terraform validate

    `

    3. Review the execution plan:

    `bash

    terraform plan

    `

    4. Provision the infrastructure:

    `bash

    terraform apply -auto-approve

    `

    Verification Steps

    Once applied, Terraform outputs the alb_dns_name.

    1. Navigate to http:// in your browser.

    2. You should see the "Enterprise Digital Delivery Platform" page successfully returned by the Nginx web servers.

    3. Verify in the AWS Console that the EC2 instances are marked as "Healthy" in the Target Group.

    Cleanup Instructions

    To tear down all resources and avoid AWS charges:

    bash
    terraform destroy -auto-approve

    Lessons Learned & Future Improvements

  • NAT Gateway Cost Optimization: To remain strictly within the AWS Free Tier, EC2 instances were placed in public subnets but locked down via strict Security Groups to simulate a private subnet architecture without incurring NAT Gateway hourly costs.
  • SSM Over SSH: Using AWS Systems Manager entirely eliminates the attack surface associated with managing and distributing .pem SSH keys.
  • Next Steps: Implement an AWS WAF association with the ALB, and migrate the domain to Route53 with an ACM certificate for HTTPS termination.

Enterprise Multi-Cloud Distributed Data Ingestion & Analytics Pipeline

📌 Executive Summary

This repository contains a production-quality enterprise multi-cloud pipeline that facilitates secure, cross-cloud communication between Amazon Web Services (AWS) and Google Cloud Platform (GCP). The entire infrastructure is provisioned autonomously using Terraform, enforcing the principles of Infrastructure as Code (IaC) and least-privilege Security via Workload Identity Federation (WIF).

🏢 Business Problem

Modern enterprises frequently operate across multiple cloud providers to leverage the distinct advantages of each. However, securely bridging isolated ecosystems—such as moving operational data from AWS into Google BigQuery for analytics—often involves the insecure practice of hardcoding Service Account JSON keys or managing long-lived secrets.

💡 Solution Overview

This project completely eliminates the need for hardcoded credentials. It establishes a direct cryptographic trust relationship between AWS IAM and GCP IAM. A serverless API in AWS safely processes data and, via an AWS IAM Role impersonation exchange, securely invokes a private, IAM-protected Google Cloud Function to ingest data natively into BigQuery.

🏗 Enterprise Architecture

The architecture consists of a highly scalable, fully serverless microservice pipeline.

End-to-End Request Flow / Workflow

1. Client initiates an HTTP POST request to the AWS API Gateway.

2. API Gateway proxies the payload to an AWS Lambda (Python).

3. The AWS Lambda assumes its execution role and dynamically fetches a short-lived Identity Token from GCP Workload Identity Federation.

4. With the cryptographically signed JWT, Lambda invokes the authenticated-only Google Cloud Function (Gen 2) over HTTPS.

5. The Cloud Function validates the payload and stream-inserts the structured record into Google BigQuery.

6. Execution traces and audit trails are persisted into Google Cloud Logging.

    🔒 Security Features

    IAM Design

    Both AWS and GCP adhere to the principle of least privilege.

  • The AWS Lambda only has basic execution permissions to emit CloudWatch logs and execute its logic.
  • The GCP Service Account is solely restricted to roles/run.invoker on the specific Cloud Function and roles/bigquery.dataEditor on the specific BigQuery dataset.

    • Workload Identity Federation

    Instead of provisioning a static Service Account Key (.json), AWS STS is linked as a trusted Identity Provider within a GCP Workload Identity Pool. The Lambda process retrieves a short-lived JSON Web Token (JWT) on the fly, guaranteeing secretless architecture.

    🚀 Deployment Flow

    1. Source Packaging: scripts/build_aws_lambda.ps1 bundles the AWS Lambda code and its dependencies into a deployment artifact.

    2. IaC Initialization: terraform init downloads the AWS, Google, and Archive providers.

    3. Infrastructure Provisioning: terraform apply -auto-approve builds out the GCP BigQuery Dataset, GCP WIF, GCP Service Account, GCP Cloud Function, AWS IAM Role, AWS Lambda, and AWS API Gateway in dependency order.

    🧪 Testing & Validation Results

  • Terraform Validation: Config syntax cleanly verified.
  • HTTP Verification: REST endpoints properly accept structured JSON and reject malformed requests with 400 Bad Request.
  • Cross-Cloud Auth Verification: AWS-to-GCP authentication strictly enforces 403 Forbidden if JWTs are malformed or missing, and securely proxies valid invocations.
  • BigQuery Verification: Rows reflect instantly in the target dataset (enterprise_pipeline_dataset.events).

    📊 BigQuery Data Flow, Logging, and Monitoring

    Data is streamed in real-time into the BigQuery table events.

    Monitoring is handled implicitly via:

  • AWS CloudWatch: Lambda execution metrics, durations, and HTTP proxy traces.
  • Google Cloud Logging: Request footprints, access audits, and BigQuery insertion logs for the Cloud Function.

    • 💰 Cost Considerations

    This project was strictly engineered to utilize Free Tier components where possible:

  • Lambda and API Gateway scale to zero with generous free invocations.
  • Cloud Functions Gen2 (Cloud Run) scales down to zero instances.
  • BigQuery incurs no costs for micro-batch inserts under the free 10 GB limit.

    • 📈 Scalability & Future Improvements

  • Asynchronous Processing: Implement AWS SQS or GCP Pub/Sub between the ingestion endpoint and the database for robust buffering under extreme loads.
  • CI/CD Integration: Integrate GitHub Actions to automatically run terraform plan and pytest on Pull Requests.
  • VPC Service Controls: Implement VPC network borders to enforce entirely private API routing across the cloud border.

    • 💡 Lessons Learned

  • Engineering a tight Workload Identity Federation boundary requires intricate awareness of the google-auth library's token exchange behaviors on AWS Lambda environments without IMDSv2 access.
  • Correctly scoping GCP IAM bindings for Service Account impersonation (roles/iam.serviceAccountTokenCreator) is critical to fetching OIDC ID Tokens for Cloud Run authentication.

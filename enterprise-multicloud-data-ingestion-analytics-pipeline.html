# Enterprise Multi-Cloud Distributed Data Ingestion & Analytics Pipeline <p align="center"> <img src="https://img.shields.io/badge/Status-Completed-success" alt="Project Status"/> <img src="https://img.shields.io/badge/Terraform-1.5+-623CE4.svg?logo=terraform" alt="Terraform"/> <img src="https://img.shields.io/badge/AWS-Services-232F3E.svg?logo=amazon-aws" alt="AWS"/> <img src="https://img.shields.io/badge/Google_Cloud-Services-4285F4.svg?logo=google-cloud" alt="Google Cloud"/> <img src="https://img.shields.io/badge/Python-3.11-3776AB.svg?logo=python" alt="Python"/> <img src="https://img.shields.io/badge/BigQuery-Analytics-669DF6.svg?logo=google-bigquery" alt="BigQuery"/> <img src="https://img.shields.io/badge/GitHub_Actions-Ready-2088FF.svg?logo=github-actions" alt="GitHub Actions"/> <img src="https://img.shields.io/badge/License-MIT-blue.svg" alt="License"/> </p> ## 📌 Executive Summary This repository contains a production-quality enterprise multi-cloud pipeline that facilitates secure, cross-cloud communication between Amazon Web Services (AWS) and Google Cloud Platform (GCP). The entire infrastructure is provisioned autonomously using Terraform, enforcing the principles of Infrastructure as Code (IaC) and least-privilege Security via Workload Identity Federation (WIF). ## 🏢 Business Problem Modern enterprises frequently operate across multiple cloud providers to leverage the distinct advantages of each. However, securely bridging isolated ecosystems—such as moving operational data from AWS into Google BigQuery for analytics—often involves the insecure practice of hardcoding Service Account JSON keys or managing long-lived secrets. ## 💡 Solution Overview This project completely eliminates the need for hardcoded credentials. It establishes a direct cryptographic trust relationship between AWS IAM and GCP IAM. A serverless API in AWS safely processes data and, via an AWS IAM Role impersonation exchange, securely invokes a private, IAM-protected Google Cloud Function to ingest data natively into BigQuery. ## 🏗 Enterprise Architecture The architecture consists of a highly scalable, fully serverless microservice pipeline. ### Architecture Diagram ```mermaid graph TD A["Client Request (HTTP POST)"] --> B["AWS API Gateway"] B --> C["AWS Lambda Python 3.11"] subgraph aws_cloud ["AWS Cloud eu-central-1"] B C end C -- "OIDC Token Request" --> D["GCP Workload Identity Federation"] subgraph gcp_cloud ["Google Cloud europe-west3"] D E["Cloud Function Gen2"] F[("BigQuery")] G["Cloud Logging"] end D -- "Returns ID Token" --> C C -- "Secure HTTPS POST (JWT)" --> E E -- "Stream Insert" --> F E -- "Execution Logs" --> G ``` ### End-to-End Request Flow / Workflow 1. **Client** initiates an HTTP POST request to the **AWS API Gateway**. 2. **API Gateway** proxies the payload to an **AWS Lambda (Python)**. 3.

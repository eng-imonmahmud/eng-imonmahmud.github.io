Enterprise Serverless GenAI Inference API

Project Status: 🟢 Production Ready

Professional Description

The Enterprise Serverless GenAI Inference API is a highly scalable, robust, and autonomous REST API engineered entirely on Google Cloud Platform's serverless infrastructure. It acts as an integration gateway to Vertex AI Gemini, exposing generative AI inference capabilities through secure endpoints.

Designed with production-grade practices, the architecture leverages Cloud Functions (2nd Gen) for execution, Cloud Build for CI/CD, and Artifact Registry for container management, adhering strictly to the principle of least privilege through refined IAM roles.

    Executive Summary

    This project demonstrates the ability to autonomously construct, deploy, and audit a completely serverless AI backend without manual intervention. It highlights a mature cloud-native engineering workflow—from generating secure boilerplate and enforcing IaC-like infrastructure to configuring deployment pipelines and interacting with large language models efficiently.

    Features

  • Serverless Compute: Zero infrastructure management leveraging Cloud Functions (2nd Gen).
  • Generative AI Integration: Direct communication with Google's Vertex AI Gemini 2.5 Flash model.
  • Stateless Execution: Ensures horizontal scaling out-of-the-box.
  • Automated CI/CD: Integrated GitHub Actions for linting and Pytest automation.
  • Enterprise Security: Uses least-privilege service accounts and .gcloudignore filtering.
  • Structured Logging: Comprehensive error handling and system-level logging.

    Deployment Architecture

    The API was deployed using the gcloud CLI. The underlying platform handles containerization, deployment to Cloud Run, and Eventarc integration automatically.

    bash
    gcloud functions deploy genai-api \
    --gen2 \
    --runtime=python312 \
    --region=us-central1 \
    --source=. \
    --entry-point=generate \
    --trigger-http \
    --allow-unauthenticated \
    --memory=512MiB \
    --set-env-vars=GOOGLE_CLOUD_PROJECT=imons-projects,GOOGLE_CLOUD_LOCATION=us-central1 \
    --service-account=genai-api-sa@imons-projects.iam.gserviceaccount.com

    ---

    Security Design & Authentication & IAM

  • Identity Abstraction: The function operates under a dedicated Service Account (genai-api-sa@imons-projects.iam.gserviceaccount.com).
  • Least-Privilege Role: The service account is strictly granted the Vertex AI User (roles/aiplatform.user) role, preventing any unauthorized broad project modifications.
  • Credential Sanitization: The repository enforces a strict exclusion policy (.gitignore and .gcloudignore) to prevent accidental leaks of .json keys, .env files, or venv structures.

    Testing Strategy

    The project implements a comprehensive Pytest suite:

    1. Endpoint Verification: Validates correct HTTP status codes (200 OK, 400 Bad Request, 500 Internal Server Error).

    2. Payload Validation: Asserts proper handling of empty or invalid JSON.

    3. Mocking: Simulates Vertex AI responses using pytest-mock to test the internal logic without accumulating cloud billing costs or network latency.

    Lessons Learned

  • Dependency Management: Utilizing Python 3.12 for Cloud Functions requires careful consideration of library compatibilities (such as protobuf). Leveraging exact requirements guarantees smooth deployments.
  • Resource Constraints: Serverless inference often requires tuning memory caps; scaling from the default 256 MiB to 512 MiB ensures the Vertex AI libraries do not face out-of-memory container terminations.

    • Future Improvements

  • API Gateway: Introduce Google Cloud API Gateway for rate limiting and API key authentication.
  • Terraform Automation: Refactor infrastructure provisioning using HashiCorp Terraform for true Infrastructure-as-Code implementations.
  • Secret Manager: Store prompt engineering templates and configuration variables dynamically in Google Cloud Secret Manager.

    • Cleanup

    To destroy the active Cloud Function and prevent recurring charges:

    bash
    gcloud functions delete genai-api --gen2 --region us-central1 --quiet

Enterprise Serverless API Gateway & Secure Microservices Architecture

Project Description

This project demonstrates a production-ready, highly secure, and automated Enterprise Serverless Architecture built natively on Google Cloud Platform (GCP). It features a Python Flask microservice containerized using Docker, continuously built via Google Cloud Build, and stored in Artifact Registry. The service is securely deployed to a private Google Cloud Run instance.

To adhere to the Zero Trust security model, the Cloud Run instance strictly blocks all unauthenticated public access. Traffic is exclusively managed and routed through a Google Cloud API Gateway, which utilizes a dedicated Identity and Access Management (IAM) service account with least privilege permissions (roles/run.invoker) to authenticate and securely invoke the private backend.

The entire pipeline, infrastructure deployment, IAM configuration, validation, and cleanup have been automated, eliminating the need for manual intervention and mitigating security risks.

Architecture Overview

The application traffic flows securely through the following path:

Internet → API Gateway → IAM Authentication (Service Account) → Private Cloud Run

Technology Stack

  • Language: Python 3.11
  • Web Framework: Flask
  • Containerization: Docker
  • CI/CD: Google Cloud Build
  • Container Registry: Google Artifact Registry
  • Serverless Compute: Google Cloud Run (Private)
  • API Management: Google Cloud API Gateway
  • Security & Auth: Google Cloud IAM (Zero Trust, Least Privilege)
  • API Specification: OpenAPI 2.0 (Swagger)
  • Scripting: Bash / PowerShell

    • Features

  • Zero Trust Security Model: Direct public access to the Cloud Run microservices is completely blocked using the --no-allow-unauthenticated policy.
  • Least Privilege IAM: The API Gateway uses a dedicated service account limited strictly to the run.invoker role.
  • Automated CI/CD: Seamlessly transitions from raw code to a deployed container image via Cloud Build and Artifact Registry.
  • API Management: Centralized routing and API specification using a fully managed Google API Gateway.
  • Infrastructure as Code (IaC) principles: Standardized deployment scripts and OpenAPI YAML for repeatable, immutable deployments.

    • Security Model

    This project stringently enforces enterprise-grade security protocols:

    1. No Public Direct Access: Attempting to bypass the Gateway and access Cloud Run directly results in a deliberate 403 Forbidden response.

    2. Explicit IAM Binding: Only the designated API Gateway Service Account possesses the precise cryptographic token authority to negotiate entry to the backend.

    3. Strict Git Ignore Policies: All local JSON credential files, PEM keys, temporary artifacts, and environmental configuration files are systematically ignored to prevent credential leakage.

    API Endpoint Documentation

    The API Gateway routes the following RESTful endpoints:

  • GET /health: Validates the operational health of the microservice.
  • GET /employees: Returns structured employee organizational data.
  • GET /projects: Returns current enterprise project statuses.
  • GET /departments: Returns departmental hierarchical data.

    Deployment & Validation Workflow

    The automated deployment pipeline performs the following sequentially:

    1. Build Phase: Cloud Build packages the app.py into a Docker image and pushes it to Artifact Registry.

    2. Deploy Phase: Cloud Run deploys the image privately.

    3. Security Phase: A Service Account is provisioned, and IAM policies bind the account to the Cloud Run service.

    4. Gateway Phase: The OpenAPI specification dynamically injects the backend URL and initializes the API Config and API Gateway.

    5. Validation Phase: Curl scripts automatically assert that the backend rejects direct traffic (403) while the gateway routes successfully (200 OK).

    • Lessons Learned

  • Enforcing a Zero Trust backend significantly bolsters the resilience of serverless applications against unauthorized invocations.
  • Decoupling API routing from the core application logic using API Gateway streamlines microservice architecture and scales effortlessly.
  • Complete end-to-end automation via scripts and pipelines dramatically reduces the time-to-market while enforcing stringent cloud-native best practices.

    • Future Improvements

  • Implement Google Cloud Armor in front of the API Gateway for WAF and DDoS protection.
  • Incorporate JSON Web Token (JWT) validation at the API Gateway level to authenticate end-users, not just the microservices.
  • Translate the imperative deployment bash scripts into declarative Terraform modules for industry-standard state management.

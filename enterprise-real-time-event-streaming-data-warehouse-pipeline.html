Enterprise Real-Time Event Streaming & Data Warehouse Analytics Pipeline

📌 Project Overview

This repository contains a production-quality serverless event-driven analytics pipeline built entirely on Google Cloud Platform (GCP). Designed with enterprise-grade architecture, the system automatically processes generated order events in real-time, performs dynamic ETL (Extract, Transform, Load) transformations, and streams the refined data directly into an Enterprise Data Warehouse (BigQuery) for analytical querying.

🏗️ High-Level Architecture

The pipeline leverages an event-driven, fully serverless architecture ensuring extreme scalability, fault tolerance, and zero infrastructure maintenance overhead.

    ⚙️ Deployment Workflow

    All resources are deployed autonomously using the Google Cloud SDK and Python client libraries.

    1. Enable necessary GCP APIs (Cloud Functions, Run, Eventarc, Pub/Sub, BigQuery, Scheduler).

    2. Provision BigQuery Dataset (enterprise_analytics) and Table (orders).

    3. Provision Pub/Sub Topic (enterprise-order-events).

    4. Deploy Cloud Function (Gen2) with Eventarc triggers.

    5. Create Cloud Scheduler Job to publish events every 3 minutes.

    🧠 ETL Workflow

    The Cloud Function (Gen2) receives the payload, executes the ETL process in Python 3.12, and dynamically generates realistic transaction IDs, geographic data, and monetary values before appending precise UTC timestamps and streaming the data into BigQuery.

    ☁️ Cloud Services Used

  • Cloud Pub/Sub: High-throughput message broker.
  • Eventarc: Event routing and orchestration.
  • Cloud Functions (2nd Gen): Serverless compute built on Cloud Run.
  • Cloud Scheduler: Fully managed enterprise cron job scheduler.
  • BigQuery: Serverless, highly scalable enterprise data warehouse.
  • Artifact Registry: Container image storage for Cloud Functions.
  • Cloud Build: CI/CD pipeline for building functions.

    • 🧪 Testing Results & Validation

    End-to-end testing confirmed that Cloud Scheduler successfully invoked Pub/Sub, which accurately triggered the Cloud Function. BigQuery successfully ingested the streaming inserts. Validation scripts confirmed the presence of new, correctly transformed data.

    • 📚 Lessons Learned

  • Leveraging Gen2 Cloud Functions provides longer timeouts and greater concurrent execution capabilities.
  • Streaming inserts to BigQuery require robust exception handling and accounting for streaming buffer flush delays.

    • 🔮 Future Improvements

  • Implement Dataflow for complex windowing operations.
  • Add Dead Letter Queues (DLQ) in Pub/Sub for failed event handling.
  • Utilize Cloud KMS for encrypting PII payload data.

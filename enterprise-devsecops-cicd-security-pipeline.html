Enterprise DevSecOps CI/CD Pipeline & Automated Security Validation

📌 Project Overview

This repository contains a production-grade, fully automated DevSecOps CI/CD pipeline built entirely on AWS using Terraform. It enforces security best practices by continuously scanning Infrastructure as Code (IaC) and application code for vulnerabilities, hardcoded secrets, and misconfigurations, establishing a Zero-Trust security approach for enterprise deployments.

💼 Business Objective

To demonstrate a highly scalable, recruiter-grade DevSecOps CI/CD pipeline capable of fully autonomous security validations. The project showcases expertise in AWS cloud architecture, Infrastructure as Code, continuous integration, and automated vulnerability management.

🛠 Technology Stack

  • Cloud Provider: AWS (eu-central-1)
  • Infrastructure as Code: Terraform
  • CI/CD Orchestration: AWS CodePipeline, CodeBuild, EventBridge
  • Storage: Amazon S3 (Source and Artifacts)
  • Security Scanners: Checkov, Trivy, tfsec, Gitleaks
  • Identity & Access Management (IAM): Least Privilege AWS IAM Roles & Policies
  • Monitoring & Logging: Amazon CloudWatch

    • 🚀 Workflows

    Infrastructure Provisioning Workflow

  • State configuration and provider initialization.
  • S3 Bucket creation with AES256 server-side encryption and versioning.
  • Granular IAM policies provisioning for EventBridge, CodePipeline, and CodeBuild.
  • CI/CD structure deployment via Terraform.

    • CI/CD Workflow

    1. Developer uploads source.zip (containing buildspec.yml and Terraform payload) to the Source S3 Bucket.

    2. Amazon EventBridge detects the Object Created event and triggers AWS CodePipeline.

    3. CodePipeline retrieves the artifact and initiates the AWS CodeBuild security validation stage.

    Security Validation Workflow

    1. Secrets Scanning: Gitleaks scans the repository for exposed API keys, tokens, and credentials.

    2. IaC Scanning: tfsec and Checkov analyze Terraform code against hundreds of security policies (e.g., CIS benchmarks).

    3. Vulnerability Scanning: Trivy scans for CVEs in the codebase and dependencies.

    4. Enforcement: If any critical vulnerability is detected, the pipeline fails immediately.

    ⚠ Known Limitation

    AWS CodeBuild Execution Blocked by Account Quota

    The infrastructure provisioning (Terraform) completed successfully and the CodePipeline triggered perfectly upon S3 upload. However, the AWS environment returned an AccountLimitExceededException preventing CodeBuild jobs from starting.

    This is because AWS places a strict 0 concurrent builds quota limit on some new Free Tier accounts to prevent cryptomining abuse. This is NOT an infrastructure or Terraform issue. The architecture, IAM policies, and Pipeline are perfectly configured, but an AWS support ticket is required to lift the account-level restriction. The project correctly demonstrates all the necessary configuration.

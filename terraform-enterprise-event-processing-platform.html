Enterprise Serverless Event Processing Platform

A production-grade, event-driven serverless architecture built on AWS using Terraform. This platform provides a scalable, decoupled system for ingesting, queuing, and processing events asynchronously.

---

🏛️ Architecture Workflow

1. Client: Submits an event payload via an HTTP POST request.

2. Amazon API Gateway: Acts as the RESTful entry point, handling routing and forwarding to the Lambda function.

3. Producer Lambda: Validates the payload, assigns a unique eventId, and enqueues the message into SQS.

4. Amazon SQS: Decouples the producer from the consumer, providing reliable message buffering and persistence.

5. Consumer Lambda: Automatically triggered by SQS events to process the queued messages.

6. Amazon DynamoDB: Stores the processed event records as the final persistence layer.

🚀 CI/CD Pipeline & Deployment

This project follows an Infrastructure as Code (IaC) CI/CD strategy.

Pipeline Workflow

1. Linting & Formatting: terraform fmt -check ensures code consistency.

2. Validation: terraform validate confirms HCL syntax correctness.

3. Planning: terraform plan outlines the required infrastructure changes.

4. Deployment: terraform apply provisions the AWS resources.

5. Security Scanning: Routine credential scanning and audit trails.

Local Deployment Instructions

1. Ensure AWS CLI is configured with correct credentials.

2. Navigate to terraform/: cd terraform

3. Initialize Terraform: terraform init

4. Deploy the infrastructure: terraform apply -auto-approve

---

🛡️ Security Audit & Best Practices

  • Least Privilege IAM: All Lambda roles explicitly define the minimal required permissions (e.g., only sqs:SendMessage for the Producer).
  • Secrets Management: No credentials, access keys, or .tfstate files are tracked in this repository. Verified by strict .gitignore patterns.
  • Data Encapsulation: DynamoDB interactions use specific partition keys to ensure exact matching and minimal scanning.

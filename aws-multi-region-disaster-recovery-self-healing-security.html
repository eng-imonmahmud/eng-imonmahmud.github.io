﻿# 🛡️ Enterprise Automated Cloud Resilience & Security Self-Healing

A Production-Grade, Multi-Region infrastructure demonstrating Event-Driven Security Auto-Remediation and Cross-Region Disaster Recovery on AWS.

---

📖 Project Overview

This repository implements a zero-trust, automated cloud security posture that instantly detects and reverses unauthorized network exposures without human intervention. Concurrently, it maintains a strict multi-region disaster recovery (DR) architecture for mission-critical data.

💼 Business Problem

Enterprise environments require robust security enforcement and immediate remediation of misconfigurations to maintain compliance and prevent data breaches. Manual intervention for security violations fails to meet strict Enterprise SLAs. Furthermore, mission-critical data must remain highly available and resilient against complete regional failures.

🏗️ Solution Architecture

The infrastructure is fully defined using Infrastructure as Code (Terraform) in a modular, enterprise-ready structure.

🚀 Security Automation Workflow

1. A user or process modifies an EC2 Security Group to allow insecure access (e.g., SSH Port 22, RDP Port 3389, or All Traffic) from 0.0.0.0/0.

2. AWS CloudTrail logs the AuthorizeSecurityGroupIngress management API event.

3. Amazon EventBridge detects this specific API call in near real-time and invokes the Self-Healing Lambda.

4. The AWS Lambda (Python Boto3) evaluates the payload, precision-targets the violating rule, and automatically issues a RevokeSecurityGroupIngress call to delete the vulnerability.

5. An Amazon SNS topic publishes an alert to the SecOps team with complete audit details.

🌍 Disaster Recovery Objectives

  • RTO (Recovery Time Objective): < 15 minutes. Cross-region S3 replication ensures the secondary bucket is continuously synced and immediately available in the event of a primary region outage in Europe.
  • RPO (Recovery Point Objective): < 5 minutes. AWS S3 Cross-Region Replication (CRR) asynchronously replicates objects almost instantaneously, ensuring minimal data loss.

    🔒 Security Controls Implemented

  • S3 Block Public Access: Enforced across all buckets.
  • IAM Least Privilege: Lambda execution role strictly limited to RevokeSecurityGroupIngress and sns:Publish.
  • Data Encryption: S3 default encryption enabled (AES256).

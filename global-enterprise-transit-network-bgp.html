🌐 Global Enterprise Transit Network & Dynamic Routing Architecture (BGP)

Project Status: 🟢 Completed & Validated

🚀 Architecture Overview

This project showcases a highly available, enterprise-grade cloud networking architecture built entirely using Infrastructure as Code (Terraform) on AWS. It demonstrates expertise in interconnecting multiple VPCs with a simulated on-premises datacenter via AWS Transit Gateway and dynamic routing (BGP) over IPsec VPN.

This architecture establishes the AWS-side infrastructure for a Hybrid Cloud environment. The dynamic BGP VPN is designed to peer with on-premises Data Center core routers (e.g., Cisco ASR / FortiGate) over an MPLS or direct internet connection. Network security inspections can be routed through Palo Alto/F5 virtual appliances in the Hub VPC.

💼 Business Problem

Modern enterprises require scalable and transitive network connectivity across dozens of VPCs and physical on-premises data centers. Point-to-point VPC peering and static routing quickly become an administrative nightmare, leading to human error, downtime, and massive operational overhead.

💡 Solution

The implementation of an AWS Transit Gateway acting as a central hub-and-spoke router, paired with AWS Site-to-Site VPN and Dynamic BGP Routing. This architecture allows for automated route propagation, high availability, and immediate scalability as new VPCs or data centers are added to the network.

🌟 Enterprise Features

  • Infrastructure as Code: 100% modular Terraform design for reusability and scalability.
  • Dynamic BGP Routing: Eliminates manual static route management, allowing networks to automatically learn new routes.
  • Hub-and-Spoke Topology: Utilizing AWS Transit Gateway for transitive routing.
  • Strict Security Posture: Least-privilege IAM roles and granular Security Groups.
  • Automated Bootstrapping: EC2 user-data auto-configures StrongSwan and FRR on Ubuntu without manual intervention.

    📐 Networking Design

    Transit Gateway Design

    The AWS Transit Gateway (enterprise-transit-gateway) is the core of this network. It uses a default route table with Route Propagation enabled. This means as soon as the VPN connects and BGP establishes, the on-premises CIDR (192.168.0.0/16) is automatically injected into the TGW Route Table, and traffic from the Production and Shared Services VPCs can natively route to it.

    Dynamic BGP & VPN Architecture

    The simulated On-Premises data center uses an EC2 instance running Ubuntu 24.04.

  • The EC2 instance is attached to an Elastic IP.
  • The Elastic IP is registered in AWS as a Customer Gateway (ASN 65000).
  • An AWS Site-to-Site VPN connection is established between the TGW (ASN 64512) and the Customer Gateway.
  • StrongSwan is used to bring up an IPsec VTI (Virtual Tunnel Interface).
  • FRRouting establishes a BGP peering session over the VTI to the AWS inside-tunnel IP, advertising the 192.168.0.0/16 network dynamically.

    • Security Architecture

  • The EC2 Router's Security Group strictly allows only necessary protocols for VPN and routing: UDP 500 (IKE), UDP 4500 (NAT-T), Protocol 50 (ESP), and TCP 179 (BGP).
  • No overly permissive 0.0.0.0/0 rules exist for SSH or management traffic, adhering to the Well-Architected Framework.

    ✅ Validation & Testing Workflow

    1. Terraform Formatting: terraform fmt -recursive ensures clean code.

    2. Terraform Validation: terraform validate ensures syntactical correctness.

    3. Secret Scanning: Custom scripts prevent accidental commits of .tfstate, AWS keys, or PSKs.

    4. AWS Console Verification: Ensured VPN tunnels transitioned to UP state and BGP routes propagated.

    🚀 Deployment Instructions

    1. Clone this repository.

    2. Ensure you have valid AWS credentials configured (aws configure).

    3. Navigate to the terraform directory: cd terraform

    4. Initialize the project: terraform init

    5. Apply the configuration: terraform apply -auto-approve

    🧹 Cleanup Procedure

    To avoid ongoing AWS charges, destroy the infrastructure when finished:

    bash
    cd terraform
terraform destroy -auto-approve

    🧠 Lessons Learned & Future Improvements

  • Automating IPsec/BGP on Linux: Extracting the dynamic VPN tunnel configuration from the Terraform aws_vpn_connection resource and injecting it cleanly into an EC2 user_data template proved to be a highly effective way to simulate an on-prem router entirely automatically.
  • Future Improvement: Implementing AWS Network Firewall in an inspection VPC to filter east-west traffic between the Production and Shared Services VPCs.

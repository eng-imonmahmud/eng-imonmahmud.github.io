Enterprise Real-Time Data Streaming & Serverless ETL Architecture

A production-ready, serverless data streaming and ETL pipeline built entirely on AWS. Designed using Enterprise best practices, Clean Architecture, and fully automated via Terraform Infrastructure as Code (IaC).

🚀 Architecture Overview

This project implements a scalable, decoupled, real-time data ingestion pipeline. It generates synthetic enterprise transaction data, buffers it, processes it in real-time, and stores it in an S3 Data Lake with dynamic time-based partitioning.

🛠️ Technology Stack & AWS Services

  • Amazon EventBridge: Cron-style event scheduling for real-time triggers.
  • AWS Lambda (Node.js 20.x): Serverless compute for both data generation and ETL transformations.
  • Amazon SQS: High-throughput message queuing to decouple producer and consumer.
  • Amazon S3: Scalable, durable object storage serving as the Data Lake.
  • AWS IAM: Strict least-privilege roles and policies.
  • Terraform: Complete Infrastructure as Code (IaC) deployment.

    ⚙️ Features

  • Decoupled Architecture: Utilizes SQS for fault tolerance and buffering.
  • Serverless Compute: Fully managed AWS Lambda functions requiring no server maintenance.
  • Dynamic Partitioning: Transformer dynamically routes objects in S3 into year=YYYY/month=MM/day=DD Hive-style partitions.
  • Security First:
  • S3 Public Access Block enabled.
  • Default S3 Server-Side Encryption (AES256).
  • Granular IAM roles restricted to exact ARN resources.
  • Idempotent Deployment: Uses Terraform for consistent, repeatable deployments.

    • 🔄 Data Flow Explanation

    1. Scheduling: Amazon EventBridge fires every 1 minute.

    2. Data Generation: The Producer Lambda generates a synthetic enterprise transaction payload (e.g., customerId, amount, currency, sourceSystem) with a PENDING status.

    3. Buffering: The Producer publishes the JSON payload to an Amazon SQS Queue.

    4. ETL Transformation: The Transformer Lambda is triggered by SQS (Event Source Mapping). It reads batches of messages, enriches the data, updates the status to PROCESSED, applies a CONFIDENTIAL classification, and extracts timestamp metadata.

    5. Data Lake Storage: The enriched payload is dynamically partitioned by year, month, and day, and persisted in the Amazon S3 Data Lake.

    🔒 Security Considerations

    During the repository audit, all potential vulnerabilities were filtered:

  • Strict .gitignore preventing commit of .terraform/, terraform.tfstate, .env, and deployment *.zip files.
  • IAM roles adhere to least privilege (e.g., Producer can only write to a specific SQS Queue; Transformer can only write to a specific S3 bucket).
  • No AWS credentials or Access Keys are hardcoded in the codebase.

    • 💰 Cost Optimization Notes

    This architecture was designed to run entirely within the AWS Free Tier:

  • AWS Lambda: 1 million free requests per month.
  • Amazon SQS: 1 million free requests per month.
  • Amazon EventBridge: Included in the free tier for standard rule evaluations.
  • Amazon S3: Standard free tier storage limits apply.

    • > *Note: Amazon Kinesis Data Firehose was explicitly avoided in this implementation to prevent unexpected billing charges for AWS Free Trial accounts.*

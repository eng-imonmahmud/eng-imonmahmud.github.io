Enterprise Cross-Cloud Disaster Recovery & Automated Object Replication Pipeline

Enterprise Architecture Overview

This repository contains a production-quality, fully serverless, and event-driven data replication pipeline. The pipeline automatically replicates objects from Google Cloud Storage (GCP) to Amazon S3 (AWS) in near real-time, functioning as a robust Disaster Recovery (DR) solution.

Business Problem

Organizations face significant risks from data loss or regional cloud outages. Vendor lock-in also prevents seamless operations during critical failures. To meet strict RPO (Recovery Point Objective) and RTO (Recovery Time Objective) requirements, companies need multi-cloud disaster recovery strategies without incurring the high costs of constantly running compute instances.

Solution

This project implements an automated, serverless replication mechanism that bridges GCP and AWS. Leveraging event-driven architecture, the solution triggers only when new data is ingested, ensuring high availability, extreme cost-efficiency, and compliance with enterprise security standards.

Key Features

  • Fully Serverless & Event-Driven: Built using Google Cloud Functions Gen2 and Eventarc. Zero idle compute costs.
  • Cross-Cloud Replication: Seamlessly transfers objects from Google Cloud Storage to Amazon S3.
  • Enterprise Security (Least Privilege): Strict IAM roles applied across both clouds. AWS Credentials are never exposed; they are injected dynamically at runtime via Google Secret Manager.
  • Infrastructure as Code (IaC): 100% automated provisioning and teardown using Terraform.
  • Robust Error Handling & Logging: Comprehensive observability via Google Cloud Logging.

    Detailed Workflow

    1. Data Ingestion: A new object is uploaded to the primary data bucket in Google Cloud Storage.

    2. Event Trigger: Google Eventarc captures the google.cloud.storage.object.v1.finalized event natively and triggers the Cloud Function.

    3. Execution & Authentication: The Gen2 Cloud Function starts. It securely fetches the required AWS IAM Access Keys injected directly from Google Secret Manager as environment variables.

    4. Data Streaming: The Python script uses boto3 and google-cloud-storage to stream the object from GCS to the destination Amazon S3 bucket.

    5. Observability: Logs are emitted to Google Cloud Logging for monitoring and audit purposes.

    Security Architecture & IAM Design

    Security was a top priority in this architecture:

  • No Hardcoded Credentials: AWS Access Keys are dynamically generated by Terraform and stored in Google Secret Manager.
  • GCP Least Privilege: The Cloud Function service account only has permissions to view objects (roles/storage.objectViewer) and access secrets (roles/secretmanager.secretAccessor).
  • AWS Least Privilege: The AWS IAM user attached to this pipeline has an explicitly defined inline policy granting *only* s3:PutObject and s3:AbortMultipartUpload for the specific destination bucket.

    Validation Process & Testing Results

    An automated validation script (scripts/validate.py) simulates a real-world scenario by:

    1. Fetching the dynamically generated bucket names from Terraform outputs.

    2. Generating a dummy DR payload.

    3. Uploading the payload to the source GCS bucket.

    4. Waiting for Eventarc to trigger the Cloud Function.

    5. Validating the successful arrival and byte-size match of the object in AWS S3.

    Cost Optimization

    By strictly utilizing Serverless offerings (GCS, Gen2 Cloud Functions, Eventarc, S3), this architecture guarantees:

  • Zero baseline cost: You are only billed for actual data stored, network egress during replication, and milliseconds of compute during the event trigger.

    • Future Improvements

  • Implement automated Terraform state management using a remote backend (like GCS or S3) with state locking.
  • Enhance the Cloud Function with an exponential backoff retry mechanism for transient AWS API failures.
  • Implement object checksum validation between GCS and S3 to guarantee data integrity post-replication.

    • Lessons Learned

  • Eventarc offers deeper integration with Gen2 Cloud Functions via CloudEvents, providing a modernized and cleaner approach compared to legacy GCS triggers.
  • Managing multi-cloud authentication introduces complexity. Leveraging GCP Secret Manager significantly reduces the attack surface compared to hardcoded .env files.
